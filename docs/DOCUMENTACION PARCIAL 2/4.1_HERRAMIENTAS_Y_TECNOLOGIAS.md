## 4.1. Herramientas y tecnologías utilizadas

El desarrollo de FashionStore combina tecnologías para la aplicación web, la aplicación móvil, los servicios del servidor y la persistencia de información. La selección permite compartir las reglas del negocio mediante una API, mantener los datos comerciales separados por empresa e incorporar operación sin conexión, reportes generativos y analítica con aprendizaje automático. También se emplean herramientas para realizar pruebas, documentar la solución y administrar su despliegue.

**Desarrollo del backend.** Se utiliza Python con FastAPI para implementar la API REST que atiende a los clientes web y móvil. El backend concentra la autenticación, la autorización, las reglas comerciales y la integración con servicios externos. Pydantic define los esquemas de entrada y salida y valida la estructura de los datos recibidos. Uvicorn ejecuta la aplicación como servidor ASGI. La organización por rutas, servicios y esquemas facilita la separación de responsabilidades y el mantenimiento de los módulos. FastAPI proporciona, además, la descripción OpenAPI de los servicios y una interfaz de documentación interactiva.

**Persistencia central y aislamiento empresarial.** PostgreSQL almacena empresas, usuarios, productos, inventarios, compras, ventas, reservas y demás registros comerciales. La conexión desde Python se realiza mediante psycopg2, utilizando consultas parametrizadas y transacciones. El esquema se administra con migraciones SQL versionadas. El modelo multitenant incorpora un identificador de empresa y políticas de seguridad por fila, denominadas Row-Level Security, junto con las validaciones del backend. La configuración local principal utiliza PostgreSQL 16, mientras que el entorno nativo de producción y el ambiente específico de pruebas de compatibilidad utilizan PostgreSQL 17.

**Aplicación web.** La interfaz se desarrolla con Angular 20 y TypeScript. HTML y SCSS permiten estructurar las pantallas y definir su presentación. Angular Router organiza la navegación; los formularios permiten capturar y validar información, y HttpClient comunica la aplicación con el backend. RxJS apoya el tratamiento de operaciones asíncronas. Node.js, npm y Angular CLI se utilizan para administrar dependencias, ejecutar el entorno de desarrollo y compilar los archivos que se publican en el servidor.

**Aplicación web progresiva y almacenamiento offline.** La versión web incorpora un manifiesto de instalación y el Service Worker de Angular para conservar los recursos necesarios para cargar la aplicación. La información comercial descargada y las operaciones pendientes se almacenan en IndexedDB mediante Dexie. Esta separación permite distinguir la caché de la aplicación de los registros que deben sincronizarse. La cola local conserva identificadores UUID, detalles, estados e intentos de envío para recuperar las operaciones después de una interrupción y procesarlas mediante el contrato de sincronización del backend.

**Aplicación móvil.** Se emplean Flutter y Dart para construir la aplicación destinada a Android. La comunicación con la API se realiza mediante el paquete http. SQLite, integrado a través de sqflite, permite conservar el catálogo descargado y las operaciones locales. Flutter Secure Storage almacena información sensible de sesión, mientras connectivity_plus permite observar cambios de conectividad. También se utilizan paquetes para generar UUID, seleccionar imágenes, solicitar permisos y abrir archivos o contenido web. La generación del APK se realiza localmente con las herramientas de Flutter y el entorno de compilación de Android.

**Autenticación y control de acceso.** La identificación de los usuarios se basa en correo electrónico y contraseña. El backend utiliza JSON Web Tokens, gestionados mediante python-jose, para validar las solicitudes autenticadas. Las contraseñas se almacenan como hashes bcrypt mediante Passlib. Los roles, permisos y contextos empresariales se comprueban en el servidor, complementando las restricciones de navegación de las interfaces. Las claves de servicios y la configuración privada se mantienen fuera del código publicado mediante variables de entorno y archivos de configuración excluidos del repositorio.

**Inteligencia artificial generativa y entrada por voz.** La integración con Google Gemini se realiza mediante el SDK google-genai. En los reportes generativos, el modelo interpreta la solicitud del usuario y devuelve una intención estructurada que el backend valida antes de ejecutar consultas permitidas. No se delega al modelo la ejecución de SQL libre. La entrada por voz utiliza las interfaces SpeechRecognition disponibles en navegadores compatibles y el paquete speech_to_text en Flutter. La transcripción se muestra como texto editable y puede sustituirse por escritura manual.

**Aprendizaje automático y analítica.** Se utiliza scikit-learn para implementar un modelo supervisado de estimación de demanda con HistGradientBoostingRegressor y un modelo no supervisado de segmentación de clientes con K-Means. NumPy permite preparar las variables numéricas; StandardScaler participa en el procesamiento de las variables de segmentación y joblib conserva los modelos entrenados. La evaluación incluye MAE y RMSE para la demanda y el coeficiente de silueta para los agrupamientos. El entrenamiento inicial emplea conjuntos sintéticos reproducibles y se ejecuta localmente. En producción se cargan los artefactos para inferencia, verificando su versión e integridad.

**Pagos, documentos y notificaciones.** Stripe se integra en modo de prueba para gestionar pagos electrónicos y recibir eventos mediante webhooks. Los documentos PDF se generan con FPDF y ReportLab, mientras openpyxl permite exportar reportes a XLSX. La integración de notificaciones push utiliza Firebase Cloud Messaging, Firebase Admin en el backend y los paquetes Firebase correspondientes en Flutter. Su habilitación requiere la configuración del proyecto Firebase y de sus credenciales. La bandeja persistente de notificaciones conserva los avisos comerciales independientemente de la recepción del push. La recuperación de contraseña incorpora envío de correo mediante SMTP y Mailpit se utiliza como servicio de correo de desarrollo.

**Imágenes y vestidor virtual.** Pillow y OpenCV apoyan la validación y el procesamiento de imágenes. El proyecto incorpora almacenamiento de fotografías mediante Cloudinary y recursos de catálogo administrados por la aplicación. El vestidor heredado integra Decart mediante su SDK web y su cliente Python para la modalidad de prueba virtual en tiempo real. También conserva alternativas configurables para la generación de imágenes. La disponibilidad de estas modalidades depende de los permisos de cámara, las credenciales y las condiciones del proveedor utilizado.

**Entorno local y despliegue.** Docker y Docker Compose organizan los servicios necesarios para el desarrollo y las pruebas locales, incluyendo ambientes de base de datos separados. El servidor de producción utiliza Debian 13 y ejecuta la aplicación de manera nativa, sin Docker. La API funciona en un entorno virtual Python 3.13 administrado por systemd. Nginx sirve la compilación de Angular y dirige las solicitudes de la API hacia Uvicorn. Cloudflared conecta el servicio con Cloudflare Tunnel para publicarlo mediante HTTPS en fashionstore.aledevcv.me. Las versiones se transfieren mediante SSH y SCP; los procedimientos incluyen respaldo y activación de la versión preparada.

**Pruebas, documentación y respaldo del código.** Pytest y TestClient se utilizan para las pruebas del backend; Jasmine y Karma para las pruebas de Angular; y flutter_test para las pruebas móviles. Playwright permite automatizar recorridos web, incluidos escenarios de operación offline. Graphify apoya el análisis de símbolos y relaciones del código, y diagrams.net se utiliza para mantener diagramas editables en formato draw.io. La documentación se conserva en fuentes Markdown y en el documento Word del proyecto. Git y GitHub permiten registrar versiones y respaldar el código, con publicación manual por parte del equipo.
